# Планировщик задач `u_schd` и главный цикл прошивки

Кооперативный планировщик fw: очередь готовых задач трёх приоритетов, отсортированные
списки программных таймеров и главный цикл, в который уходит `main()` после загрузки.
Устройство одинаково в 4.1.0.1000 и 6.2.0.1000 **[обе]**.

Метки: **[код]** — по листингу, **[стр]/[выз]** — роль по лог-строкам или вызовам.
Запись адреса: `имя` 0x… — адрес 6.2; «/ 4.1 0x…» — адрес той же функции в 4.1
(по совпадению тела, таблице [NAMES-FROM-62](../4.1/docs/NAMES-FROM-62.md) или имени
в `4.1/src/asm/fw/blocks.json`); если в 4.1 имя другое, оно указано. Функции без
пометки 4.1 — соответствие в 4.1 не установлено. Структурные адреса данных
(0x803c54, 0x803c5c, 0x803c80, 0x8004a0) — 6.2.

## 1. Постановка задач и таймеров **[код]**

Первый аргумент `u_schd__add`/`u_schd__schedule` — обработчик (адрес колбэка
минус 0x8c0000), а не период **[обе]**.

* **`u_schd__add` 0x8c3248 / 4.1 0x8c2ac8**: `(обработчик−0x8c0000,
  арг1, арг2, приоритет<3)`; берёт запись задачи `u_schd__alloc_task` 0x8c32f8 / 4.1 `u_schd__alloc_entry` 0x8c2b88
  (пул 0x803c80, обнуляет 0x1c Б, при пустом пуле фатал 0x1063), кладёт
  обработчик/аргументы в +0x0c/+0x10/+0x14 и ставит в очередь приоритета
  `u_schd__enqueue_ready` 0x8e0bcc / 4.1 0x8dc8ec: бит приоритета в gp-маске готовности,
  очереди по 12 Б с 0x803c5c. Приоритет ≥3 — фатал 0x1065. 33 места вызова
  (ISR, WBE, TX_API, автоматы соединения).
* **`u_schd__schedule` 0x8e0c0c / 4.1 0x8dc92c**: `(обработчик, a1, a2,
  a3, задержка, a5, a6)`; задержка < 0x11 — фатал 0x1068; под запретом
  прерываний дедлайн = задержка/16 + текущее время (`u_schd__now` 0x8e9524 —
  чтение таймера через объект gp+0x74) и вставка `u_schd__insert_timer`
  0x8e0c74 / 4.1 `u_schd__insert` 0x8dc99c в сортированный список таймеров 0x803c54[1] (сравнение `time_cmp`
  0x8e91bc / 4.1 0x8e431c), при смене головы — перевзвод `u_schd__arm_timer`
  (0x8e249c). 55 мест вызова.
* `u_schd__expire_timers` 0x8da674 / 4.1 `u_schd__run_expired` 0x8c55c4 — обработка истечения: для обоих списков
  0x803c54[0..1] выбирает истёкшие (`u_schd__pop_expired` 0x8c62c8) и
  перевзводит аппаратный таймер. Вызов — из бита 2 user-ICR
  ([HW-DRIVERS §2.2](HW-DRIVERS.md#22-user-icr-хоста-0x880b50-код)).
* **`u_schd__cancel` 0x8c8de0 / 4.1 0x8c7794** (десятки мест: «delete pending TO» в PSC, BA,
  MLME): ручка ≠ NULL (иначе фатал 0x1069) и взведена (байт +0x19, иначе
  0x106a); под запретом прерываний ищет её в обоих списках 0x803c54[0..1],
  снимает, при смене головы активного списка перевзводит таймер, затем
  освобождает запись (`mem_pool__free_locked` 0x8cb028 / 4.1 0x8c93f4).
  `timer_task__cancel` 0x8c8e74 / 4.1 0x8c783c — обёртка: отменяет, если ручка в объекте +0x10
  не нуль, и обнуляет её.
* Аппаратный таймер планировщика: `u_schd__hw_timer_set_compare` 0x8e9160 и
  `u_schd__program_hw_timer` 0x8e9500 — срок в 0x88024c (переходник
  `u_schd__hw_timer_set_compare_thunk` 0x8c3bec); `u_schd__irq_ack_thunk`
  0x8e94f4 — квитирование user-ICR из `u_schd__arm_timer`.
* Прочие блоки 6.2 **[код]**: `u_schd__init_queue` 0x8d9118 / 4.1 0x8d6088,
  `u_schd__arm_timer` 0x8e249c, `u_schd__calc_next_deadline` 0x8cc4c8 / 4.1 0x8ca2a0,
  `u_schd__deadline_less` 0x8cc28c / 4.1 0x8ca070, `u_schd__reschedule` 0x8e91fc,
  `u_schd__invoke_callback` 0x8c64d4 / 4.1 0x8c5804, `u_schd__fill_task_b` 0x8e6f88 / 4.1 0x8e204c.
* Сторожевые таймеры автоматов почти все — пара «`u_schd__schedule` при входе в
  ожидание / `u_schd__cancel` при событии»: `pcp_start__cancel_timer` 0x8d8750 / 4.1 0x8d53d8,
  `pcp_stop__cancel_timer` 0x8d8778 / 4.1 0x8d5400, `PS_ASSOC_SM__ps_cancel_schd_reenter`
  0x8e12e4 / 4.1 0x8dd178, три `*_psc_*_wb_timeout_event` (`sta_psc_sm__psc_resp_rx_wb_timeout_event`
  0x8c69ac, `pcp_psc_sm__m_psc_resp_tx_wb_timeout_event` 0x8c69e8 / 4.1 0x8c5c30,
  `sta_psc_sm__m_psc_req_tx_wb_timeout_event` 0x8c6a0c / 4.1 0x8c5c74), `conn__check_field_50`
  0x8c68d4 (снимает таймер соединения в +0x50), `conn__arm_retry_timer` 0x8e48d0 / 4.1 0x8dfc14.

## 2. Главный цикл **[код]**

`u_schd__run` 0x8e76a8 / 4.1 `u_schd__large_task_warn` 0x8e2454 — главный цикл прошивки, в него уходит `main()`
(`fw_main` в 6.2, шаг 22 «SCHEDULER STARTS» в
[HW-DRIVERS §1](HW-DRIVERS.md#1-загрузка-main-прошивки)):
запуск таймера планировщика (`u_schd__timer_init` 0x8e9508 — инициализация
объекта таймера gp+0x74 и двух аппаратных таймеров через
`power__start_two_timers`), инициализация двух списков таймеров
(`u_schd__init_queue`), затем бесконечно:

1. `u_schd__pop_ready` 0x8cc534 / 4.1 `u_schd__pick_next` 0x8ca30c — достать следующую готовую задачу: под
   запретом прерываний берёт старший бит gp-маски готовности (`norm`), индекс
   < 3 (иначе фатал 0x1064), снимает голову очереди 0x803c5c + 12·prio, при
   опустевшей очереди гасит бит.
2. Засекает время, вызывает `задача->fn(a1, a2)` (+0x0c/+0x10/+0x14); если
   длительность больше порога по адресу 0x8004a0 — печатает «LARGE TASK: FUNC
   address 0x%x, duration» (мс); освобождает запись.
3. Нет задач — `deep_sleep_enter` 0x8c87c0 / 4.1 0x8c71b8 (решение о глубоком сне), затем под
   запретом прерываний: если маска готовности пуста — `sleep` до прерывания.

Вся работа прошивки после загрузки — задачи трёх приоритетов, поставленные ISR
и таймерами через `u_schd__add`/`u_schd__schedule`.

## 3. Соответствие имён 4.1 ↔ 6.2 **[стр]/[выз]**

| роль | 4.1 | 6.2 |
|---|---|---|
| главный цикл с предупреждением «LARGE TASK» | `u_schd__large_task_warn` 0x8e2454 | `u_schd__run` 0x8e76a8 |
| выборка готовой задачи | `u_schd__pick_next` 0x8ca30c | `u_schd__pop_ready` 0x8cc534 |
| выделение записи задачи | `u_schd__alloc_entry` 0x8c2b88 | `u_schd__alloc_task` 0x8c32f8 |
| вставка таймера | `u_schd__insert` 0x8dc99c | `u_schd__insert_timer` 0x8e0c74 |
| обработка истёкших таймеров | `u_schd__run_expired` 0x8c55c4 | `u_schd__expire_timers` 0x8da674 |
| тик | `u_schd__tick` 0x8d756c | — |

Полный перечень блоков 4.1 — [4.1/docs/MISC.md §11](../4.1/docs/MISC.md#11-планировщик-задач-biaw-в-ucode-41).
В файлах данных 6.2 (`6.2/ref/NAMES-EXTRA.txt`, `ANNO-fw.json`) часть блоков
планировщика записана под другими именами —
[6.2/docs/MISC-FW.md, приложение А](../6.2/docs/MISC-FW.md#приложение-а-имена-блоков-в-файлах-данных-ref).
