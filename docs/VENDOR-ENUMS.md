# Вендорские перечисления

Перечисления (имя типа, значение = имя константы) из файлов глобалов пака 11ad версии 7.5:
`globals/<соседний чип wil6436, ревизия B0>/{fw,ucode}_image_globals.xml`. Это описания соседнего
чипа wil6436, а не Sparrow; для Sparrow они применимы там, где номера сверены с кодом.

## Применимость к Sparrow

Номера совпадают с кодом 4.1.0.1000 и 6.2.0.1000 везде, где проверено **[пак]**+**[код]**:

| перечисление | где применяется |
|---|---|
| `ucode_bf_state_e`, `ucode_bf_substate_e` | состояния BF в логе ucode и в `BF DONE … STATE/SUBSTATE` лога fw (расшифровка пар вида `10:51` — см. [../6.2/docs/BENCH.md](../6.2/docs/BENCH.md)) |
| `fui_bi_cfg_params_bi_mode_e` | режим BI (приём / передача маяка / discovery-маяк / одиночный направленный маяк) |
| `fui_abft_responder_mode_en_e`, `fui_valid_beacon_type_e` | режим ответчика A-BFT и тип маяка, на который он отвечает |
| `fui_cmds_lmac_personality_personality_e`, `fui_cmds_lmac_personality_failure_policy_e` | личность LMAC (активная/пассивная) и политика при отказе BF |

Каждое прочее применение к Sparrow проверять по коду.

Обозначения: константы, в имени которых стоит название соседнего чипа, записаны как
`‹wil6436 …›` (например, `RF_‹wil6436 A1›` — тип РЧ-модуля соседнего чипа ревизии A1). Повтор одного
номера у двух имён (`2=EDMG_BW_CAPACITY_UNSUPPORTED, 2=EDMG_BW_CAPACITY_MAX`) — так в паке: второе
имя является границей перечисления.
