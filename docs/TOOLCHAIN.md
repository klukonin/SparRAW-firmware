# Тулчейн ARC и гейт кодировок

Какой тулчейн собирает прошивку Sparrow (wil6210), с какими ключами, и насколько
точно его ассемблер воспроизводит байты вендорского образа. Относится к обеим
версиям: **[4.1]** — FW 4.1.0.1000, **[6.2]** — FW 6.2.0.1000.

## Тулчейн

| параметр | значение |
|---|---|
| пакет | пребилд Synopsys `arc_gnu_2021.03` (elf32, little-endian, Linux), релиз `arc-2021.03-release` на GitHub, ~369 МБ |
| состав | **binutils 2.36.1 + GCC 10.2.0**, «ARCompact/ARCv2 ISA elf32 toolchain - build 581» |
| каталог | `toolchain/arc_gnu_2021.03_prebuilt_elf32_le_linux_install/` в корне репозитория |
| префикс | `arc-elf32-` (`gcc`, `g++`, `as`, `ld`, `objcopy`, `objdump`) |
| процессор | **`-mcpu=arc600`** |

**Почему `arc600`.** Прошивка использует `mulu64` — расширение MUL64 линейки ARC600.
При `-mcpu=arc700`, `arcem`, `archs` ассемблер эту инструкцию отвергает. Отсюда же
уточнение ядра Sparrow: ARCompact с MUL64.

### Установка

```sh
tools/get-toolchain.sh
```

Скрипт скачивает архив `arc_gnu_2021.03_prebuilt_elf32_le_linux_install.tar.gz` в
`./toolchain`, распаковывает, удаляет архив и печатает версию `arc-elf32-as`. Если
каталог уже есть, ничего не делает. Нужна именно эта версия: гейт сверен с ней.

Путь задаётся в `4.1/config.mk` и `6.2/config.mk` (`ARC_DIR`, по умолчанию
`../toolchain/arc_gnu_2021.03_prebuilt_elf32_le_linux_install`; переопределяется).

### Проверка

```sh
make toolchain-check   # в 4.1/ или 6.2/
```

Проверяет, что `$(AS)` существует, печатает его версию и собирает пробный
`mulu64 r2,r1` с `-mcpu=$(ARC_CPU)`: «mulu64 принят: -mcpu=arc600 верный».

### Ключи компилятора

| ключ | зачем | 4.1 | 6.2 |
|---|---|---|---|
| `-mcpu=arc600` | MUL64, см. выше | да | да |
| `-Os -ffreestanding -fno-builtin -nostdlib -ffunction-sections -fdata-sections -fno-common -Wall` | базовые | да | да |
| `-mno-sdata` | без него gcc адресует глобалы через `gp` (`ld_s r0,[gp,0]`), а `gp` прошивки — её собственный указатель данных | да | нет |
| `-ffixed-r25` | в ucode `r25` — указатель кольца команд MAC (2485 обращений); без флага gcc может взять `r25` под переменную и восстановить его в эпилоге, молча откатив кольцо. На текущем коде флаг не меняет ни одного байта | да | нет |
| C++: `-fno-exceptions -fno-rtti -fno-threadsafe-statics -fno-use-cxa-atexit` | `CXXFLAGS` | да | `CXX`/`CXXFLAGS` не определены |
| `LIBGCC` (`gcc -mcpu=arc600 -print-libgcc-file-name`) | трамплины милли-кода gcc, см. [REWRITING.md](REWRITING.md) | да | да |

Значения `gp` прошивки: fw **[4.1]** `0x800170`, fw **[6.2]** `0x800184`, ucode —
`0x800528` в обеих версиях (цели `anno` в `Makefile`).

## Гейт кодировок

Вопрос гейта: выдаёт ли внешний ассемблер ровно те байты, что лежат в образе.

```sh
make gate              # в 4.1/ или 6.2/
```

Цель вызывает `tools/asm_gate.py ref/ASM-REFSET.txt --as … --ld … --objcopy …
--cpu arc600`, печатает итог и список расхождений; код возврата ненулевой, если
расхождения есть (для текущих эталонов это ожидаемо — см. ниже).

### Метод

* Эталон `ref/ASM-REFSET.txt` — строки `REF <адрес> <байты> <частота> <текст Ghidra>`,
  снимается скриптом `tools/asm_refset.py` (исходный вариант —
  `SparRAW-tools/re/asm_gate.py` и `SparRAW-tools/re/ghidra/asm_refset.py`, эталон
  `SparRAW-tools/re/ghidra/ASM-REFSET-4100.txt`).
* **[4.1]** 377 инструкций: 180 самых частых форм и 197 «экзотических» (`mlo`/`mhi`,
  регистры `r32`–`r63`, `abs`/`adc`/`mulu64`); всего в образе 4742 различных формы.
  **[6.2]** 367 инструкций.
* Каждая инструкция собирается **в отдельный файл и линкуется по своему настоящему
  адресу** (`ld -Ttext=<addr>`), затем байты сравниваются с оригиналом.
* Переходы на числовой адрес собираются через внешний символ
  (`ld --defsym __t=<addr>`), а при неудаче — через локальную метку на нужном
  расстоянии (`.space`); если нормализованный текст не совпал, пробуется исходная
  запись Ghidra.

Ограничения gas, определившие метод:

1. **Нельзя собирать набор одним файлом через `.org`.** gas проверяет слот задержки
   по соседним инструкциям в потоке, игнорируя заполнение от `.org`, и выдаёт
   «Insn bl has a jump/branch instruction in its delay slot» для инструкций, которые
   в образе далеко друг от друга.
2. **Числовой адрес перехода gas разрешает при ассемблировании** относительно начала
   секции (нуля), а не через релокацию: смещения выходят неверные, а короткие формы
   (`b_s`, `lp`) отвергаются как «immediate out of bounds». Отсюда подстановка
   символа и `--defsym`, для коротких форм — метка на расстоянии.

### Нормализация Ghidra → GNU as

Расхождения в записи, а не в кодировке (функция `normalize()` в `tools/asm_gate.py`,
её же использует `tools/gen_asm_tree.py`):

| Ghidra печатает | gas требует | почему |
|---|---|---|
| `j_s blink`, `j.d blink` | `j_s [blink]` | косвенный переход в скобках |
| `st.as r0,[gp,-0x28]` | `st.as r0,[gp,-0xa]` | Ghidra даёт байтовое смещение, поле `.as` масштабируется на 4 |
| `lsr r0,r45,1` | `lsr r0,r45` | сдвиг на 1 — отдельный опкод, двухоперандная форма |
| `add_s r0,0x1`, `sub_s sp,0x8` | `add_s r0,r0,0x1` | компактные формы в gas трёхоперандные |

Классы расхождений:

* **Выбор кодировки** (`add_s`, `asl_s`): у ARC несколько равноправных компактных
  кодировок одной операции; для широкого непосредственного операнда (u7) GNU as 2.36
  выбирает другую форму (u5 или 32-битную).
* **`mulu64`**: различается поле `a` (приёмник), которое при MUL64 не используется:
  вендорский компилятор пишет туда номер регистра первого операнда (`r0` → 0,
  `r2` → 2, `r19` → 0x13; в 4.1 все случаи с `r0`), gas — 62 (`0x3e`).
* **Нули, разобранные как код** **[6.2]**: `00000000` в образе — заполнение, которое
  Ghidra показывает как `b` на собственный адрес.
* **Запись Ghidra** **[6.2]**: `sync 0x0` — gas принимает `sync` без операнда;
  в правила нормализации не внесено.

Ни один случай не является ограничением тулчейна: такие инструкции выдаются в
дереве исходников сырыми байтами (см. ниже).

## Полная пересборка

Гейт проверяет выборку форм; полная проверка — пересборка сегментов кода целиком:

```sh
make tree && make rebuild && make fw
```

`make rebuild` собирает `fw_code` и `uc_code` и сверяет их с вендорскими сегментами
(`tools/cmp_seg.py`); `make fw` упаковывает образ `build/wil6210-selfbuilt.fw` и, если
в дереве нет переписанных блоков (**[6.2]** — и примененных патчей quilt), сверяет его
с вендорским `.fw` побайтово (`--verify-against`). Без правок обе версии дают
вендорский образ побайтово. **[6.2]** Дополнительно `make plain-gate` — обычная сборка
(блоки подряд, без прибитых адресов, `PLAIN=1`) с пустым каталогом замен.

### Сырые байты: `ref/RAW-*.txt`

Инструкции, которые gas кодирует иначе, в `src/asm/…` выдаются как `.byte` с
комментарием-текстом инструкции. Список строит `tools/gen_raw.py`: каждая инструкция
ставится на свой адрес через `.org` (так расхождение длины не сдвигает хвост и список
выходит минимальным), сегмент собирается, байты сравниваются. Если сырая инструкция
стоит в слоте задержки, предшествующий переход с суффиксом `.d` тоже уходит в сырые
байты: ассемблер не считает `.byte` инструкцией и подставил бы в слот следующую живую.

Причины сырых инструкций: компактные `add_s`/`sub_s`/`asl_s`/`asr_s` с u7;
`j`/`bl` с limm на абсолютный адрес вне сегмента (gas кодирует короткой формой без
limm); заполнение нулями, разобранное как `b .`.

| файл | сырых адресов | из них нули | подтянуто из-за слота задержки |
|---|---|---|---|
| `4.1/ref/RAW-fw.txt` | 878 | — | — |
| `4.1/ref/RAW-uc.txt` | 587 | — | — |
| `6.2/ref/RAW-fw.txt` | 3324 | 2262 | 91 |
| `6.2/ref/RAW-uc.txt` | 687 | 25 | 14 |

## Не установлено
