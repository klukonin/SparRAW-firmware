# Сводка LINK_STATS и дамп PHY

В 6.2 из печати 4.1 вырезаны сводка `LINK_STATS` (PPDU/CCA, обработанные PPDU, ложные
тревоги, INA/SFD sync), поотчётные строки `### LINK STATS` (соседние маяки, NAV,
keep-alive, принятые RTS) и большая часть дампа `[PHY_LOG]`. Данные в 6.2 остались —
переложены. В 6.4 печать возвращена блоками на C:
`link_stats__phy_counters`, `link_stats__calc_goodput`, `phy_stats__dump`
(`6.4/src/c/fw`).

## LINK_STATS

`link_stats__report` (4.1 0x8e2ae8, 6.2 0x8e7cf8) зовётся по таймеру
`link_stats_sm__arm_report_timer` с тем же периодом 0x186a0; сводка в 4.1 — каждый 10-й
отчёт, в 6.2 — каждый 100-й **[код]**.

| поле | 4.1 | 6.2 | уровень |
|---|---|---|---|
| PPDU_REP_CNT / CCA2_TO_CCA3 | 0x886ecc биты 8..13 / 16..21 | тот же регистр; 6.2 читает только бит 3 | регистр [код], смысл бит в 6.2 [гипотеза] |
| HANDLED_PPDUS | 0x857048 | **0x857034** — ucode `rx_flow__run` 0x93139e, 0x931694 | [код] |
| FA_IN/OUT_TXOP_* | 0x854d88…0x854d9c | **0x853928…0x85393c** (total 0x853924) | адрес [код]; писатель статическим сканом не найден, на стенде счётчики растут [железо] |
| PHY_INA_SYNC_CP / DP | 0x8839a0 / 0x8839a0 (ошибка 4.1: DP = CP) | 0x8839a0 / **0x883964** | [код] |
| PHY_SFD_SYNC_CP / DP | 0x8839b0 / 0x883974 (ошибка 4.1: это SFD timeout) | **0x8839a4 / 0x883968** (SFD sync) | [код] |
| beacon_neighbor, _aw | 0x857014, 0x857018 (ucode `rx_nav_bi_step`) | **нет**: аналог `rx__update_nav_from_frame` 0x9343a8 счётчика не ведёт; адреса заняты кодом ассерта ucode | [код] |
| beacon_nav | 0x857044 | **0x857030** — развёртка маяка 0x923db8 | [код] |
| KA_cnt / KA_fail_cnt | 0x857000 / 0x857010 | **0x857000 / 0x857004** — `internal_tx__flow_sm2` 0x939164, 0x939470 | [код] |
| rx_txop_rts | 0x857040 | **0x85702c** — `rx_get_required_response` 0x933238 | [код] |

Общий блок 0x857000 в 6.2 переложен: +0x0c/+0x10 — ассерт fw, +0x14/+0x18 — ассерт
ucode, +0x40 — маска пиров, +0x44…+0x63 — счётчики FWQ, +0x50 — маска CID с данными в
очереди. Механический перенос смещений 4.1 даёт мусор **[код]**.

`link_stats__calc_goodput` 6.2 на деле считает PER (неуспешные · 100 / все передачи за
период) **[код]**.

## Дамп PHY

`phy_stats__dump` 6.2 стоит в том же слоте таблицы методов периодической службы
PHY-монитора (0x8007a0 + 0x0c), что `phy_monitor__task_step` 4.1 (0x800740 + 0x0c), и
снимает те же 14 регистров в структуру той же раскладки (`phy__read_rx_counters` 6.2 /
`hwd_phy__snapshot_status` 4.1) **[код]**:

| смещение | регистр | счётчик |
|---|---|---|
| +0x00 / +0x1c | 0x883964 / 0x8839a0 | INA sync, SC/DP / CP |
| +0x04 / +0x20 | 0x883968 / 0x8839a4 | SFD sync |
| +0x08 / +0x24 | 0x883974 / 0x8839b0 | SFD timeout |
| +0x0c / +0x28 | 0x88396c / 0x8839a8 | HEADER_CRC_OK |
| +0x10 / +0x2c | 0x883978 / 0x8839b4 | HEADER_CRC_ERROR |
| +0x14 / +0x30 | 0x883970 / 0x8839ac | BER_LAST_ZERO |
| +0x18 / +0x34 | 0x88397c / 0x8839b8 | BER_LAST_NON_ZERO |

Время последнего сброса счётчиков — [0x800524] (`phy_stats__get_cfg_word`, пишет
`hwd_phy__rx_statistics_clear`); температуры — 0x85380c (активный РЧ), 0x853808
(baseband); ложные тревоги — 0x853924/0x85393c. 6.2 вычисляла время и TSF, но
выбрасывала **[код]**.

Период: 4.1 — 100 000, 6.2 — 10 000 000 в единицах мкс. Тик таймера `u_schd` — 16 мкс
(`<<4` даёт мкс): на стенде между дампами `curr_tm` растёт на 625 000, TSF — на 10,01 с
**[железо]**. Дамп 6.2 — раз в 10 с.

## Стенд [железо]

AP под нагрузкой: сводка, поотчётные строки (NAV 0, KA 0, rx_txop_rts ~120 за отчёт) и
дамп PHY печатаются; FA_IN_TXOP_DD ≈ 25 тыс., FA_OUT_TXOP_AD ≈ 440 за сводку;
температуры совпадают с ответом `WMI_TEMP_SENSE`.
