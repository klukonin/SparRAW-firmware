# Приёмный тракт микрокода 6.2

Таблица станций ucode 6.2, поиск станции по адресу, отладочный захват кадров,
конфигурация приёма ответа и замеры приёма. Автомат BF, SLS и BRP —
[../../docs/BF-ENGINE.md](../../docs/BF-ENGINE.md); NAV, TXOP и CTS —
[../../docs/DATAPATH.md](../../docs/DATAPATH.md) §3.

Метки: **[код]** — по декомпиляции Ghidra проекта 6.2, **[железо]** — пара
6.2↔6.2. Host-адрес для `mem_addr`/`mem_write`: `0x940000 + (A − 0x800000)`.

## 1. Таблица станций

**`0x801104 + 0x50·sta`** (база по `ucode_cmd_0x05_handler` и
`ucode_cmd_0x18_handler`: `r13 = 0x801104 + 80·sta`), sta = 0…7 (8 —
широковещательная). Смещения ниже даны **от 0x801100** (так их удобно читать на
железе); от настоящей базы они на 4 меньше. Очереди станции для запрета TX
(+0x1c/+0x20 от 0x801100 = +0x18/+0x1c от базы) — [../../docs/DATAPATH.md](../../docs/DATAPATH.md) §8.

| смещение | смысл | источник |
|---|---|---|
| +0x06 | флаги, бит 0 = запись занята | `sta_tbl__find_by_mac` **[код]** |
| +0x08 | RF-цепь станции (сектор приёма, 0x801108 + 0x50·sta) | `rx_resp__finish_restore_rx` **[код]** |
| +0x0c | **TX-вектор ответа**: байт 1 (биты 8..15) = Sector ID; уходит MAC-командой `0x3f000000 \| [+0x0c]` перед ответом на индивидуальный кадр станции | `rx_flow__handle_frame` **[код]**; живьём AP `0x2e30` → сектор 46, STA `0x2d30` → 45, совпадает с debugfs `bf` **[железо]** |
| +0x10 | биты 8..22 — **индекс RX-сектора «направленного omni»**: 96+sta, либо **0x7fff = обычный quasi-omni** | `brp_update_omni_sector_idx` **[код]**; живьём STA `0x6020` (96), AP `0x7fff20` **[железо]** |
| +0x34..0x39 | MAC-адрес станции (адреса SSW-Feedback — 0x801134..0x801138) | **[код, железо]** |
| +0x4f (0x80114f) | флаг, пишет LMAC 0x18 с полем типа 0/4 → 1, типа 1 → 0 | `ucode_cmd_0x18_handler` **[код]** |
| **+0x51 (0x801151)** | **число секторов соседа** для окна RSS (живьём 64) | `ucode_cmd_0x18_handler` **[код, железо]** |

Пример: поле +0x10 станции 0 — host `0x941110`.

## 2. Разбор принятого кадра **[код]**

* `sta_tbl__find_by_mac` 0x9349a0 — поиск станции по MAC в таблице §1
  (сравнение трёх полуслов с +0x34, флаг +0x06 бит 0); возвращает 0…8.
* `rx_capture__match_filter` 0x93e56c — сравнение принятого кадра с отладочным
  фильтром захвата (+0x24 станция, +0x25 режим, +0x26 «MCS 0», +0x27 MCS, +0x28
  бит `0x801424`; 0xff = любой), при совпадении запоминает параметры кадра.
  Используется механизмом `0x803134/0x803140` в начале `rx_flow__handle_frame`
  (действия 1 → `rx_meas__append_sample`, 2 → `rx_meas__finish_with_8830ec`, 3 →
  `rx_meas__capture_frame`, 5 — переключение режима).
* `0x92f2bc` — три MAC-команды подряд `0x3d000400`, `0x1f003000`, `0x06000000`
  (выход из приёма кадра).
* `0x9343a8` (`rx__update_nav_from_frame`) — обновление NAV, см.
  [../../docs/DATAPATH.md](../../docs/DATAPATH.md) §3.4.
* Кадры SSW — `sls__rx_ssw_frame`, [../../docs/BF-ENGINE.md](../../docs/BF-ENGINE.md) §8.1.

## 3. Конфигурация приёма ответа **[код]**

`tx_ctx__alloc_next` 0x9384d4 (в корреляции `uses_tbl_801108__9384d4`): контексты
передачи — двойной буфер `0x802978 + 0x3c·k`, текущий в `0x8029f0`. При выделении
для станции **`0x801024 := [0x801110 + 0x50·sta]`** (поле +0x10 — «направленный
omni»), **только если оно не 0x7fff**; иначе в `0x801024` остаётся значение от
предыдущего контекста. `0x801024` — текущая конфигурация приёма (по ней
настраивается приём ответа, её же использует `abft_resp__parse_fdbk` для сдвига
номера сектора).

Следствие: у AP, чей BRP провалился (поле станции = 0x7fff,
[../../docs/BF-ENGINE.md](../../docs/BF-ENGINE.md) §9, §10.2), ответы этой станции
(CTS, ACK, SSW-Feedback) принимаются с **устаревшей** конфигурацией, оставшейся
от последнего удачного контекста или маяка — вероятное звено цепочки «нет CTS»
**[гипотеза]**; проверка — живьём `0x941024` против `0x941110`.

`rx_resp__finish_restore_rx` 0x9336d8 — завершение любой ответной передачи:
конфиг приёма (MAC 0x1d, AWV `0xcac000/0xcac100` из `0x800748`), затем RF-цепь на
сектор станции +0x08 (`0x801108 + 0x50·sta`), если узел не в роли 2 при фазе
0x100; набор RX в `0x889488`. Отладочный снимок (`0x857358 + 0x60·n`, n ≤ 9, на
10-м — `uc_sysassert 0x144b`).

## 4. Замеры приёма **[код]**

* `rx_meas__capture_frame` 0x927f6c, `rx_meas__append_sample` 0x928854,
  `rx_meas__finish_with_8830ec` 0x92893c.
* `rx_flow__measure_snr_select_best` 0x92d688 — среднее 8 выборок таблицы
  `0x80183c` по индексу `0x883830`[6:0]; это phy_rx_signal_gain_adc_db, а не RSSI
  (`6.2/ref/REGS-62.md`).
* `rx_flow__accumulate_busy_time` 0x924960.

## Не установлено

* Значение `0x801024` на AP в момент провала CTS (проверка гипотезы §3).
* Назначение действия 5 механизма захвата `0x803134/0x803140`.
