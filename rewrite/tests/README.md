# Тесты прошивки (pytest)

Проверка нового образа перед выпуском: статически, по дереву исходников и на стенде из двух узлов.

```sh
cd rewrite
python3 -m pytest tests --fw <образ.fw>                          # образ: структура, CRC, метка, строки журнала
ARC_DIR=<тулчейн> python3 -m pytest tests/test_tree.py           # дерево: сборка без предупреждений, proto.h, fwsh
python3 -m pytest tests --fw <образ.fw> --stand tests/stand.toml \
        [--ko wil6210.ko] [--peer-fw <образ>] [-m 'not slow']     # всё, включая стенд
```

Без `--stand` стендовые тесты пропускаются, без `--fw` — проверки образа. Стенд описывает `tests/stand.toml`
(образец — `stand.example.toml`; сам файл в git не кладётся). Журналы упавших стендовых тестов (dmesg и журнал fw
обоих узлов) — в `--artifacts` (по умолчанию `test-artifacts/`).

## Что проверяется

| файл | метки | что |
|---|---|---|
| `test_image.py` | image | записи образа целые, CRC и длина заголовка, версия `X.Y.Z.B-SparRAW[-PRO]`, запись-метка проекта, сегменты данных — в известных областях без перекрытий, таблицы своих строк журнала (fw, uc) |
| `test_tree.py` | tree | чистая сборка fw.elf и uc.elf без предупреждений, `fw/proto.h` актуален, адреса общего блока fw/uc совпадают, образ из дерева проходит `test_image` |
| `test_sta.py` | stand, sta | dut — станция: загружена именно проверяемая версия, нет ошибок FW, ping, пропускная способность в обе стороны (пороги в `stand.toml`), нет разрывов под нагрузкой, в журнале fw нет фатальных ошибок; переподключение после перезапуска точки (известная проблема — xfail) |
| `test_ftm.py` | stand, sta, pro | только SparRAW-PRO: измерения FTM, слово +0x0e адресата не останавливает FTM, SESSION_END: PARAMS_ERROR для канала вне 0..3 (BUSY стендом не воспроизвести — сессия короче передачи команды) |
| `test_sta_robust.py` | stand, sta | неверные значения в командах хоста — отказ с записью в журнале, fw жива, связь есть |
| `test_ap.py` | stand, ap | dut — точка, peer — станция на том же образе (vendor-станция 6.2 к точке по стандарту не идёт: B43 маяка, 9.3.4.2): подключение, ping, пропускная способность, останов точки без ошибки |

Порядок прогона задаёт `conftest.py`: станция → FTM → неверные команды → точка (смена роли — перезагрузка
узла). Тест, оборвавший связь, не портит следующие: фикстура роли проверяет связь и при необходимости
перезагружает стенд. После теста AP peer возвращается в роль точки на своей прошивке (`fw_backup`).

## Стенд

Два узла OpenWrt с wil6210 (Sparrow) по ssh с ключом, питание dut — розетка Tapo
(`SparRAW-tools/host/tapo_plug.py`): каждая загрузка образа — через power-cycle, настройки — `uci` без commit.
`--ko` — свой модуль драйвера: ставится сразу после загрузки узла (интерфейсы тогда `phy1-*`).
