# Сниффер на узле: захват кадров через регистратор пакетов MAC (PMC)

Статус: драйвер реализован (ветка `feat/drv-capture` драйвера, `capture.c`, `pmc.c`), разборщик проверен на
дампах стенда (`tools/pmc_decode_test.py` драйвера). Ручные опыты E0–E3 (запись регистров через `mem_write`, дамп
`pmcdata`) прошли на .12 2026-11-03: связь не страдает (ping 0,8 мс, FWERR 0, ассоциация держится). Первый прогон
потока (.12 STA к vendor AP, 12 с с переподключением, кольцо 256 × 2048) — 543 кадра, Wireshark разбирает DMG Beacon,
SSW, SSW-FB, SSW-Ack, RTS, CTS, BA, CF-End, mgmt, данные; но 220 потерь синхронизации на 306 буферов и последний
байт TA в принятых кадрах = 0 — разбор в 3 и 4, исправления после e619ab1. Область — **open** (отладка IFS, TXOP,
BlockAck, SLS).

Прежняя схема (копия кадров uc в кольцо в общей памяти, WMI 0x0f14/0x1f14, `fw/rxcap.c`, `uc/rxcap.c`)
**отменена**: fw эту команду не получит, uc не трогаем. Бит возможностей 24 снова `RAW_MODE` (vendor), не наш.

Цель. Пока нет внешнего сниффера (LHG 60G), каждый узел стенда пишет то, что **принял** (кадры, которые MAC отдаёт
в очереди) и **всё, что передал сам**. Поток идёт в сетевой интерфейс `wilmon<N>` с заголовками Radiotap
(DLT_IEEE802_11_RADIO) для `tcpdump`/Wireshark. Сеанс включается командой в debugfs с обязательным лимитом времени;
по истечении драйвер останавливает захват сам. AP/STA при захвате работает как обычно.

Обозначения: **[стенд]** — видно на дампах стенда; **[гипотеза]** — не проверено.

## 1. Решения коротко

| вопрос | решение |
|---|---|
| Кто пишет кадры | Регистратор пакетов MAC (PMC) — аппаратный блок со своим DMA-кольцом 7 в памяти хоста. uc и fw в записи не участвуют. |
| Роль fw | Только настройка кольца 7: `WMI_PMC` (0xf04f) op 0 — база и размер кольца, op 1 — сброс очереди 7 (`fw/wmi_h_misc.c:wmi_pmc`, `fw/dma_ring.c:dma_mgr_configure_ring`). Есть и в vendor fw. |
| Роль драйвера | Выделяет кольцо, пишет регистры PMC, опрашивает кольцо раз в 2 мс (прерываний нет), разбирает поток записей, строит Radiotap, отдаёт в `wilmon<N>`, возвращает буферы аппаратуре. |
| Что попадает | RX: кадры, которые MAC отдал в очередь (маяки и mgmt → fw; данные → хост — только по запросу, `rxqos`), плюс `a7`+`af` о каждом PPDU. Байты Ack/BA/RTS/DMG CTS/CF-End/SSW/SSW-FB пира **не** пишутся **[стенд]** — драйвер строит по `af` **синтетический** кадр (раздел 4.2, `rxsynth`, по умолчанию вкл.). TX: все свои кадры — SSW, SSW-FB, SSW-Ack, RTS, DMG CTS, BA, CF-End, mgmt, QoS Null; данные — только по запросу (`txqos`) **[стенд]**. |
| Данные (`rxqos`, `txqos`) | **По умолчанию выкл.**: с записями данных AP под нисходящим iperf ~950 Мбит/с повис целиком за секунды (нет ping, нет netconsole — похоже на остановку шины/PCIe) **[стенд 2026-11-04]**; без них тот же AP держит 985 вниз и 910 вверх, записано 74 940 TX-записей control/mgmt без потерь. Включаются только явно (`mask=…,txqos`), тогда предупреждение в dmesg и в `capture`. |
| Длина | До `max_data` двойных слов на тип (по умолчанию 63 = 252 Б). Кадр длиннее — усечён, флаг в vendor-поле. У A-MPDU — свои записи длины, байтов и статуса на каждый MPDU (4, «A-MPDU»); кадр в pcap — первый MPDU. |
| Переполнение | Кольцо заполнено — PMC теряет записи (счётчик `full`), обычный приём не страдает **[гипотеза, опыт E4]**. |
| Интерфейс | `wilmon%d` — netdev `ARPHRD_IEEE80211_RADIOTAP`, не wdev cfg80211; создаётся при первом `start`, живёт до `close`/выгрузки. |
| debugfs | `/sys/kernel/debug/ieee80211/phyN/wil6210/capture`: `start <сек> [опции]`, `stop`, `close`; чтение — состояние и счётчики. |

Почему не vendor-режим sniffer (`WMI_CFG_RX_CHAIN.sniffer_cfg`): он перестраивает RX-MACQ и канал, останавливает
маяк — узел перестаёт быть AP/STA. Годится только для отдельного узла-сниффера.

## 2. Регистры PMC (Sparrow, окно RGF, адреса 1:1)

Источник карты — vendor debug-tools (`host_manager_11ad/PmcCommandHandler/PmcRegistersAccessor.cpp`, ветка
`BASEBAND_TYPE_SPARROW`); значения — по `PmcSetConfigHandlerSequences.cpp` и опытам E1–E3.

| адрес | имя в драйвере | поля / значение |
|---|---|---|
| 0x88607c | `PMC_CTL` | [15:0] разделитель записей `0xcafe`; б16 `rec_en_set`, б17 `rec_en_clr`, б18 `rec_active` (чтение), б20 — запись остановлена ошибкой **до сброса чипа** (чтение; после 0x88608c = 0 и 0x886080[27:16] = 0xfff), б21 — запись остановлена ошибкой, новый пуск её снимает (чтение; поле [27:16] 0x886080 не равно размеру буфера) **[стенд 2026-11-14, 2.4]**, б24 `rx_en`, б25 `tx_en`, б26 `ucode_event_en`, б27 `idle_sm_en` |
| 0x886080 | `PMC_IF_CFG` | б0 `intf_type`=1, б2 `dma_if_en`=1, [27:16] **размер буфера кольца 7 в единицах 8 Б** (0x100 — 2048 Б); драйвер пишет `bufsize`/8 (ветка `unified` 0719f5a; прежде всегда 0x100) **[стенд 2026-11-14, 2.4]** |
| 0x88608c | `PMC_CFG_8C` | `0xfc` (как vendor). Число, не маска: 0xff, 0x80, 0x7c, 0x40, 0x20 и 0xfc без любого одного бита — запись идёт; 0x10 — запись встаёт, связь рвётся (2 из 2); 0x08, 0x04, 0x01, 0 — запись встаёт (`PMC_CTL` б20) до перезагрузки. Порог/тайм-аут тракта записи, минимум между 0x10 и 0x20 **[стенд 2026-11-14, 2.4]** |
| 0x886094 / 0x8860ac | `PMC_RX_QID` / `PMC_TX_QID` | маска **исключаемых** очередей MAC: б N = 1 — кадры очереди N не пишутся; драйвер ставит 0 — все (ветка `unified` e2b724a; модуль стенда ещё со старым значением 1 — `rdrun.sh` `POSTCAP`) **[стенд 2026-11-14, 2.3]** |
| 0x886098 | `PMC_RX_MASK` | б0 qos, б1 mgmt, б2 control, б3 beacon, б4 error, б5 phy |
| 0x8860a4 | — | б0 = 1 (после сброса): в `af` RX-записи — RX-отчёты MAC R36..R39 (w2..w5) и `af.w0` б7; 0 — w2..w5 нули, б7 = 0, синтетические кадры строить не из чего; драйвер не пишет **[стенд 2026-11-14, 2.4]** |
| 0x88609c / 0x8860a0 | `PMC_RX_MAXD0/1` | `max_data` RX, двойные слова, байт на тип: 0x88609c — типы б0..б3, 0x8860a0 — б4..б5 |
| 0x8860b0 | `PMC_TX_MASK` | б0 qos, б1 mgmt, б2 control, б3 beacon, б4 direct |
| 0x8860b4 / 0x8860b8 | `PMC_TX_MAXD0/1` | `max_data` TX: типы б0..б3 и б4 |
| 0x886200 | `MAC_PRS_CTRL_0` | б16 `pmc_post_dec_mode` |
| 0x886eb8 / 0x886ebc | `RGF_TSF_LO/HI` | TSF MAC, мкс |
| 0x8815ec | IS кольца 7 | б6 `is_pmc_dma` (ставит fw) |
| 0x8815f8 | `PMC_RING_SW_TAIL` | последний индекс, который отдан аппаратуре; fw ставит d−1 |
| 0x881620 | `PMC_RING_SW_HEAD` | позиция записи аппаратуры **[гипотеза]** |
| 0x886084, 0x886088, 0x8860a8, 0x8860bc | — | только чтение (запись 0 не меняет значения): 1 — в покое и при исправной записи; после остановки ошибкой (`PMC_CTL` б20/б21) 84, 88, a8, bc = 0, 88 бывал и 2 — признаки состояния (готовность/пустота FIFO?) **[стенд 2026-11-14, 2.4]** |

Единица `max_data` — двойное слово **[стенд]**: 8 → 32 Б, 0x40 → кадр данных 222 Б целиком. Байт 0 регистров
`max_data` — qos-данные **[стенд 2026-11-14]**: 0x3f080402 в 0x88609c и 0x8860b4 режет RX и TX A-MPDU и TX QoS Null до
8 Б (2 двойных слова), control и маяки — как были; драйвер пишет `dsnap` в байт 0, `snap` в остальные. Значение 0x40
(256 Б) принимается, запись всё равно не длиннее 256 Б.
Тактирование PMC (0x880c20 б9) уже включено записью direct_write vendor, её переносит `build_fw.py`.

### 2.1. Пуск (драйвер, `wil_cap_pmc_regs_start`)

```
0x886080 = 0x00000005 | (bufsize/8)<<16      (2048 Б → 0x01000005; до 0719f5a — всегда 0x01000005)
0x88608c = 0xfc
0x886094 = 0;  0x8860ac = 0         (маска исключаемых очередей: все пишутся, 2.3; до e2b724a — 1)
0x886098 = RX-маска;  0x8860b0 = TX-маска
0x88609c = d | s<<8 | s<<16 | s<<24;  0x8860a0 = s | s<<8      (s = snap/4, d = dsnap/4)
0x8860b4 = d | s<<8 | s<<16 | s<<24;  0x8860b8 = s
0x886200 = v | 0x10000        (v сохраняется)
0x88607c = 0x0300cafe         (rx_en, tx_en — только для непустой маски)
0x88607c = 0x0301cafe         (rec_en_set)
```

Если при старте `rec_active` уже стоит (ручной опыт, прежний драйвер) — сначала останов.

### 2.2. Останов (`wil_cap_pmc_regs_stop`)

```
0x88607c = 0x0000cafe; пауза 1 мс (PMC сбрасывает свой буфер в DMA)
0x88607c = 0x0002cafe         (rec_en_clr), ждать снятия б18 до 10 × 0,5–1 мс (иначе счётчик stop_busy)
0x886200: вернуть только б16 к сохранённому значению (прочие биты могли смениться)
```

### 2.3. Маска очередей `PMC_RX_QID` / `PMC_TX_QID` (стенд 2026-11-14)

Запись в регистр во время захвата (debugfs `mem_write`, `tools/stand/rdrun.sh` `POSTCAP`), образ open, iperf вверх и
вниз, записи данных включены (`rxqos,txqos`); есть ли TX-/RX-записи вида на узле:

| QID (RX = TX) | TX A-MPDU точки | TX A-MPDU станции | TX BlockAck | TX DMG CTS | RX A-MPDU |
|---|---|---|---|---|---|
| 0 | есть | есть | есть | есть | есть |
| 1 (прежнее значение драйвера) | есть | **нет** | есть | есть | есть |
| 2 | нет | есть | есть | есть | есть |
| 3 | нет | нет | есть | есть | есть |
| 0xff | нет | нет | нет | есть | нет |
| 0xffffffff | нет | нет | нет | нет | нет (≈30 из 40 тыс.) |

Бит N исключает очередь MAC N: данные станции идут очередью 0, данные точки — очередью 1, BlockAck и принятые
данные — одной из очередей 2–7, DMG CTS — очередью ≥ 8. RTS, CF-End, SSW (прямая передача, `PMC_TX_MASK` б4) маской
очередей не отсекаются ни при каком значении. Единица (vendor-значение, «маска qid = 1» прежней таблицы) выключала
запись данных станции — у неё не было ни одной TX-записи A-MPDU, сумма SIFS BlockAck по одному узлу не считалась.
Кадры, не отданные в очередь (`af.w0` [23:16] ≠ 0, 4.2), маска не касается. Регистры остальных узлов блока (0x886000…
0x8860fc) от записи QID не меняются.

## 3. Кольцо 7

- Дескрипторы — формат `vring_tx_desc` (32 Б), буферы `dma_alloc_coherent`. Драйвер заполняет буфер образцом
  `0xB0BA0000 | номер слова` (как vendor), дескриптор: адрес, `length` = размер буфера, `status` = 0, `d0` = б9
  **без `DMA_IT`** (иначе ложные прерывания RX_DONE).
- `WMI_PMC` op 0 (ALLOCATE) — fw ставит базу, размер, `SW_TAIL` = d−1, б6 IS, номер кольца 7 в `PRP_CTRL[11:8]`.
  Кольцо той же геометрии при новом `start` переиспользуется: все дескрипторы заново, `WMI_PMC` op 1 (сброс
  очереди 7), затем op 0. Иначе — освобождение и новое выделение. По умолчанию после `stop` кольцо освобождается
  (op 1 + память), `keep=1` оставляет его до `close`.
- **Поток байтов непрерывен**: аппаратура заполняет буферы целиком и подряд, записи переходят через границу буфера
  **[стенд: дамп из 175 буферов по 1024 Б разбирается сквозным проходом]**. Частично заполнен только последний
  буфер при останове — хвост остаётся образцом.
- **DU — не признак готовности буфера [стенд 2026-11-03]**. Первый прогон потока брал буферы по DU и получил
  `resync` = 220 на 306 буферов (`bufs_du` = 306, `bufs_head` = 0). В pcap — запись маяка, оборванная на смещении
  1024 буфера в 2048 Б: в MPDU слова образца `0xB0BA0100`, `0xB0BA0101`…, то есть DU уже стоял, а вторая половина
  буфера ещё не была записана; аппаратура дописывала её в уже возвращённый буфер, поток в следующем буфере
  начинался с середины записи. Буферы на стенде заполняются медленно (≈ 25 в секунду при опросе раз в 2 мс), поэтому
  почти каждый буфер читался недописанным.
- Готовность буфера i теперь — по данным (аппаратура пишет поток по порядку, буферы при возврате заполняются
  образцом): записано последнее слово буфера i (`by_last`) **или** записано первое слово буфера i+1 (`by_next`).
  Буфер с DU без этих признаков ждёт следующего опроса, счётчик `du_early` (один раз на буфер) — прямое
  наблюдение раннего DU. При останове (PMC выключен) забирается всё записанное. Буфер, закрытый аппаратурой не до
  конца (запись обрывается образцом, поток идёт дальше в следующем), разбор принимает без потерь (раздел 4.1),
  счётчик `part`.
- Возврат: буфер заново заполняется образцом, дескриптор — как при выделении (`status` = 0), затем `wmb()` и
  `SW_TAIL` = индекс последнего разобранного. Аппаратура пишет до `SW_TAIL` − 1 (один буфер — зазор).
- Задержка: кадр виден хосту, когда заполнится его буфер. Меньший `bufsize` — меньше задержка при редких кадрах.
  Размер буфера аппаратура берёт из 0x886080[27:16] (единица 8 Б), не из дескриптора: поле должно быть равно
  `bufsize`/8 (2.4).

## 4. Формат записей **[стенд]**

Little endian. Запись: `fe ca LEN TYPE` + LEN байт данных, дополнение нулями до 4 Б. LEN — один байт (≤ 255).
Разделитель 0xcafe — младшие 16 бит `PMC_CTL`.

**TX** (свой кадр), группа `55 56 57 58 59`:

| тип | LEN | данные |
|---|---|---|
| 0x55 | 0 | начало |
| 0x56 | 4 | u32 длина MPDU **с FCS** |
| 0x57 | ≤ max_data | MPDU **без FCS** (с Frame Control), до `max_data` |
| 0x58 | 0 | конец |
| 0x59 | 12 | u32 TSF[31:0] мкс, затем 8 Б сведений (`info0`, `info1`; например 0x0680, 0x0500) |

Группа `55 58 59` без 56/57 — свой кадр типа, не включённого в TX-маску (или без заголовка), счётчик `tx_nohdr`.
TSF стоит после 58 и означает **начало PPDU** (как у RX-записи `a7`) **[стенд 2026-11-14]**: (1) у своих DMG Beacon
поле Timestamp кадра равно метке TX-записи у 17 663 из 17 663 — одна защёлка TSF; (2) на одном узле «RX BlockAck −
TX A-MPDU − TXTIME(A-MPDU)» = 3,9 мкс при длине A-MPDU 0…60 КБ (без вычета TXTIME — 8…255 мкс), «TX BlockAck − RX
A-MPDU − TXTIME» — так же: обе метки стоят в начале PPDU. `info1` у TX и RX — всегда 0 (кроме испорченных записей).
**У кадров, которые MAC шлёт сам (Ack, немедленный BA, DMG CTS, CF-End, RTS, SSW, SSW-Feedback, BRP, ATIM), вместо
TSF бывает 2 или 6 [стенд]**: BlockAck и Ack — 2, прочие — 6. Режим целиком на узел и загрузку: либо у всех таких
кадров код, либо у всех верная метка; кадры очередей (A-MPDU, QoS Null, DMG Beacon) — всегда с меткой. Стенд
2026-11-14, 14 захватов: точка (.11) — коды во всех; станция (.12) — в 6 из 14 коды, в 8 метки, независимо от
образа (cf1/es1) и от QID (2.3: при QID 1 и 2 бывало и так, и так). Снимок 0x886000…0x8860fc у узла с кодами и узла с
метками одинаков (кроме своих адресов) — переключатель режима вне блока PMC. Прежде: AP 2026-11-04 — 87 762 из
249 834 TX-записей, STA в `our_raw_12` — 7412, STA в прогоне 2026-11-04 — ни одной. Разборщик такие метки
отбрасывает (4.1); сумма SIFS без калибровки (`air_judge` `calibration_free_sum`) на узле с кодами не считается.

**RX**, группа `a7 a8 ab ae af`:

| тип | LEN | данные |
|---|---|---|
| 0xa7 | 8 | u32 TSF[31:0] мкс (начало PPDU), u32 `info0` = длина PSDU с FCS [..:6] \| б5 A-MPDU \| DMG MCS [4:0] (0x0500 — 20 Б, MCS 0; одиночный MPDU — = длине `a8`, A-MPDU — длина PSDU) **[стенд]** |
| 0xa8 | 4 | u32 длина PSDU/MPDU **с FCS** |
| 0xab | ≤ max_data | байты MPDU с Frame Control; при полной длине за ними 4 Б FCS (`trailer`, драйвер отдаёт отдельно): [23:0] = младшие 24 бита CRC-32 переданного кадра (сверка с TX-записью того же кадра на другом узле — 99 %, ~2600 пар на опыт), [31:24] записан как 0 **[стенд 2026-11-14]** |
| 0xae | 4 | u32 статус — только у кадров, отданных в очередь (данные): б8 = 1 всегда (0x100); б0 = 1 — только при R38 б30 (`fcs_ok_full`) = 0, обратное неверно (у .12 б30 = 0 при б0 = 0 — 9499 из 47 605); прежде видели и 0x0a00 **[стенд 2026-11-14]** |
| 0xaf | 24 | w0 статус PMC (поля — 4.2), w1 — всегда 0, w2..w5 — RX-отчёты MAC R36, R37, R38, R39 (раздел 4.2) **[стенд]** |

`a7 af` и `a7 ae af` без `ab` — PPDU, не отданные в очереди (чужие Ack/BA, кадры не нам и т. п.), счётчик
`phy_only`. На дампах это основная масса записей (3416 групп против 176 кадров за 5 с).

**Нулевые байты RX [стенд 2026-11-14]**. Сверка RX-записи кадра с TX-записью того же кадра на другом узле (A-MPDU
из одного MPDU целиком, ~2000–3500 пар на опыт): в RX записаны как 0 байты MPDU 9, 25, 41, … (9 + 16k), байт 15
(последний байт TA данных, только он из 15 + 16k), последний байт MPDU и старший байт FCS. У DMG Beacon байт 9 —
последний байт BSSID: отсюда прежнее «последний байт TA = 0». С `postdec=0` (б16 `MAC_PRS_CTRL_0` не ставится), с
`fixta=0` и с обоими — то же самое: это тракт записи RX, не поиск пира и не драйвер. Байт TA драйвер
восстанавливает по таблице пиров (4.1, `fixta`); остальные нули не восстановить (последний байт MPDU и FCS[31:24]
известны только по TX-записи пира).

**A-MPDU: записи на каждый MPDU [стенд 2026-11-14]**. В группе PPDU (`a7` … `af`) у A-MPDU на каждый MPDU — своя
тройка `a8 ab ae` (длина с FCS, байты до `max_data`, статус); в `our_raw_12` — 37 групп из 2…8 MPDU. TX — по всей
видимости так же: при `max_data` qos 8 Б TX-кадр прежнего драйвера был 8·N Б **[гипотеза: сырой дамп TX-записей
данных не снят; разборщик считает новым MPDU и вторую `56`, и вторую `57`]**. Прежний разборщик дописывал
байты всех MPDU в один кадр до 256 Б (отсюда «длина 256 > 252»: байты 252…255 — Frame Control и Duration второго
MPDU, у 22 642 из 22 642 таких кадров равны байтам 0…3; при `max_data` 8 Б — 8·N Б из начал MPDU) и брал длину и
статус последнего MPDU. Теперь (ветка `unified` 0719f5a) кадр — первый MPDU со своими длиной и статусом, прочие
MPDU пропускаются, счётчик `more` (групп с пропуском). Отдавать каждый MPDU отдельным кадром (с общими `a7`/`af`) —
не сделано: при `max_data` 28 Б это заголовки всех MPDU (номера, повторы).

Статус `ae` — свой у каждого MPDU: прежнее «б0 = 1 только при R38 б30 = 0, обратное неверно» — статус последнего
MPDU против признака FCS всего PPDU; б0 — ошибка FCS этого MPDU **[гипотеза]** (`af.w0` [23:16] — число MPDU с
ошибкой FCS).

Счёт `pmc_bf.bin` (маски RX 0x3f, TX 0x1f, `max_data` 0x40, переподключение STA): TX SSW 320, SSW-FB 3, SSW-Ack 1,
RTS 2, CF-End 11, QoS Null 5, mgmt 13; RX DMG Beacon 158, QoS Data 18.

### 4.1. Разбор (драйвер, блок `PMC_PARSER_BEGIN..END` в `capture.c`)

- Буферы идут в порядке кольца. Поток — записанная часть каждого буфера: до хвоста из слов образца
  (`0xB0BA0000 | номер слова`), найденного с конца. На границе записи: `fe ca` — запись; иное — потеря
  синхронизации (одна на эпизод), поиск следующего `fe ca` по словам. Счётчик `resync` и разбивка по причинам:
  `start` — с первого слова буфера (поток не продолжился из предыдущего буфера: тот прочитан недописанным или
  потерян), `garbage` — не разделитель и не образец после записи внутри буфера, `hole` — слова образца внутри
  записанной части, `carry` — сразу после записи, дочитанной из предыдущего буфера (её продолжения там не было),
  `torn` — запись, оборванная концом потока (останов).
- Запись, не помещающаяся в записанную часть буфера, копируется в буфер переноса (≤ 260 Б) и дочитывается из
  следующего; так же переживается буфер, закрытый аппаратурой не до конца (`part`).
- Группы RX и TX ведутся раздельно. `a7` открывает RX-группу (предыдущая закрывается), `af` — закрывает;
  `55` открывает TX-группу, `59` — закрывает. Запись группы вне открытой группы — `orphan`; неизвестный тип —
  `unknown`, пропускается по длине.
- Кадр: `mpdu_len` = длина − 4; `caplen` = min(байт данных, `mpdu_len`); `caplen < mpdu_len` — флаг TRUNC;
  нет записи длины — флаг NOLEN.
- TSF до 64 бит: `t = base + (s32)(t32 − (u32)base)`, `base` — предыдущая принятая метка; перед первым буфером
  каждого опроса — полный TSF, прочитанный из 0x886eb8/0x886ebc в этом опросе (`wil_pmc_set_ref`). Переход через
  2^32 мкс (71,6 мин) учитывается.
- Проверка метки: принимается, только если `t` не старше TSF опроса на 4 с и не новее на 1 с (записи ждут в
  кольце обычно миллисекунды). Иначе — флаг TSF_BAD (`sflags` б7), счётчик `tsf: bad`, Radiotap TSFT нет, `tsf` =
  последняя принятая метка (не TSF опроса — тот на задержку кольца позже), так что кадр встаёт в pcap на своё
  место. Раньше метки 2/6 (раздел 4, TX) принимались: pcap AP откатывался назад на десятки секунд (70 924 шага,
  «длительность» 93 с при захвате 30 с). Так же отбрасываются метки старой базы после скачка TSF (STA принимает TSF
  точки). При TSF узла меньше 4 с от сброса метка 2/6 пройдёт проверку — допущение.
- Порядок записей в потоке совпадает с порядком меток: на `our_raw_12` после отбраковки 7413 меток время pcap
  (`ts=tsf`) не идёт назад ни разу, длительность 5,956 с = времени опросов по часам хоста.
- RX, восстановление TA (`fixta=1`, по умолчанию): смещение последнего байта TA по Frame Control
  (IEEE 802.11-2020 9.3.1: mgmt и данные — 15; control BAR/BA/PS-Poll/RTS/CF-End — 15, CTS/Ack — нет TA;
  control frame extension Poll/SPR/Grant/DMG CTS/Grant Ack/SSW/SSW-FB/SSW-Ack — 15, DMG DTS — нет; DMG Beacon —
  9). Байт как записан — в vendor-поле `ta_raw` (флаг TA). Пиры — подключённые станции всех VIF (`wil->sta[]`,
  у STA это AP), опрос добавляет их в таблицу сеанса (32 записи, ушедшие пиры остаются). Если первые 5 байт TA
  совпали с пиром, а последний байт равен CID пира или 0 (и пир с этими 5 байтами один), байт заменяется
  адресом пира: флаг TA_FIXED, `ta_cid` = CID пира, счётчик `ta fixed`; иначе кадр как есть, счётчик
  `ta unknown`. Пир, у которого последний байт адреса и есть записанный, — кадр не трогается.
- При останове открытые группы закрываются, недочитанная запись — `resync`.
- RX: DMG MCS — `a7.info0[4:0]` (= R38[24:20] на всех кадрах дампа) идёт в vendor-поле `mcs` и у записанных кадров;
  слот R39 — в поле `slot`.

### 4.2. Синтетические кадры из `a7`+`af` (`rxsynth`)

Кадры, которые MAC завершает сам (Ack, BlockAck, BAR, RTS, DMG CTS, CF-End, SSW, SSW-Feedback, SSW-Ack, Grant,
Poll, SPR, Grant Ack, DMG DTS, QoS Null) и кадры не нам, в очередь не идут — байтов (`ab`) нет. Но по **каждому**
принятому PPDU PMC пишет `a7` (TSF начала, длина PSDU, MCS) и `af` (24 Б: статус PMC + RX-отчёты MAC) **[стенд]**.

Поля `af` **[стенд, дампы нашего fw]**:

| слово | поле |
|---|---|
| w0 | [7:0] = 0x80: б7 — w2..w5 записаны (0x8860a4 б0, 2.4); [15:8] — число MPDU в PPDU (A-MPDU: равно длине PSDU / ~1560 Б у полных, 1–3 у ACK TCP; одиночный кадр — 1); [23:16] — число MPDU, **не отданных в очередь** (одиночный control/QoS Null — 1, «б16» прежней таблицы; A-MPDU — MPDU с ошибкой FCS, всегда при R38 б30 = 0); [31:24] — число пустых разделителей A-MPDU (10.12.3, MPDU Length = 0), насыщение 255: k·(N − 1) при N MPDU, k = 50/38/26/13/7/1 на MCS 8/7/6/4/3/2 — подкадр короткого MPDU дополняется до ~1,03 мкс эфира (296 Б на MCS 8, 248 Б на MCS 7) **[стенд 2026-11-14]** |
| w2 = R36, w3 = R37 | детекторы: R36 0x201 у BA; R37 б0 RTS, б1 CTS, б16 CF-End, б24 SSW, б25 SSW-FB, б26 SSW-Ack |
| w4 = R38 | [10:8] индекс пира (CID передатчика), б11 — индекс верен; [24:20] MCS; б29, б30 — FCS в порядке; б28 сосед; б31 отчёт верен |
| w5 = R39 | [13:8] слот таблицы 3 парсера (CAM по Frame Control) — тип кадра; б15 — CDOWN = 0 (SSW); б27 — адрес получателя совпал (кадр нам) |

Слот → Frame Control. Правила таблицы 3 (прочитаны на стенде, `tools/testdata/parser_table3.txt` драйвера) держат
ключ FC[11:2] в w0[9:0]; FC = ключ << 2, проверено тестом на всех 35 правилах и по IEEE 802.11-2020 Table 9-1 /
Table 9-2 (control frame extension: type 1, subtype 6, FC[11:8] = расширение):

| слот | кадр | FC (LE u16) | класс |
|---|---|---|---|
| 0x00 | DMG Beacon (type 3, subtype 0) | 0x000c | bcn |
| 0x01..0x0c | Assoc Req 0x0000, Assoc Resp 0x0010, Reassoc Req 0x0020, Reassoc Resp 0x0030, Probe Req 0x0040, Probe Resp 0x0050, Beacon 0x0080, ATIM 0x0090, Disassoc 0x00a0, Auth 0x00b0, Deauth 0x00c0, Action 0x00d0 | | mgmt |
| 0x0f | Action No Ack | 0x00e0 | mgmt |
| 0x10 | Grant Ack (ext 7) | 0x0764 | ctrl |
| 0x17..0x1c | BAR 0x0084, BA 0x0094, PS-Poll 0x00a4, RTS 0x00b4, CTS 0x00c4, Ack 0x00d4 | | ctrl |
| 0x2c | QoS Null | 0x00c8 | data |
| 0x30..0x34 | Poll 0x0264, SPR 0x0364, Grant 0x0464, DMG CTS 0x0564, DMG DTS 0x0664 (ext 2..6) | | ctrl |
| 0x35 | CF-End | 0x00e4 | ctrl |
| 0x36..0x38 | SSW 0x0864, SSW-Feedback 0x0964, SSW-Ack 0x0a64 (ext 8..10) | | ctrl |
| 0x3c..0x3f | QoS Data: 0x0088, To DS 0x0188, From DS 0x0288, оба 0x0388 | | data |

Остальные слоты правил не имеют: кадр не строится, счётчик `no_rule`.

Кадр строится для RX-группы без `ab` с `af.w0` б16 = 1 (группа без `ab`, отданная в очередь, — это кадр типа, не
включённого в маску, его не синтезируем):
- FC слота; Duration 0 (не известен);
- RA (кроме DMG Beacon) — свой адрес (основной интерфейс; какой VIF совпал, R39 не говорит) при R39 б27, иначе
  `ff:ff:ff:ff:ff:ff` (настоящий RA не известен; так и у DMG CTS не нам). У CF-End RA может быть и широковещательным
  (9.3.1.6), б27 их не различает;
- TA там, где он есть по 9.3.1 (то же правило, что у восстановления TA: нет у Ack, CTS, DMG DTS; DMG Beacon — BSSID
  на месте 4..9), — адрес пира с CID из R38[10:8] при б11 (таблица CID → адрес пополняется каждым опросом из
  `wil->sta[]`, последний пир на CID); иначе нули;
- остальное — нули до длины PSDU из `a7` минус FCS (Wireshark видит верную длину; тела нет — SSW-поле, BA-битмап,
  QoS Control нулевые, CDOWN 0 в SSW ничего не значит — смотреть флаг CDOWN0), не больше 256 Б (флаг TRUNC);
  `a7` без слова сведений — только заголовок, флаг NOLEN;
- Radiotap: TSFT из `a7` (то же расширение до 64 бит), Flags BADFCS при R38 б29/б30 ≠ 11, vendor-поля `mcs`
  (`a7.info0[4:0]`), `cid`, `slot`, `sflags` и `phy` = сырые слова `af`.

`sflags`: б0 SYNTH — кадр построен, байты не записаны; б1 RA_OWN; б2 RA_UNKNOWN (RA = ff…); б3 TA_PEER (`ta_cid` =
CID); б4 TA_UNKNOWN (TA нули); б5 BAD_FCS; б6 CDOWN0 (R39 б15); б7 TSF_BAD (метка отброшена, 4.1 — у любого
PMC-кадра, не только синтетического).

DMG Beacon, не отданный в очередь (чужие BSS, ~3000/с на стенде), строится только с `rxsynthbcn` (по умолчанию выкл.,
счётчик `bcn_skipped`).

Счёт `our_raw_12` (наш fw, STA .12 к AP, 2026-11-03, `capture_raw`): BA 5415, CF-End 2764, DMG CTS 1926, RTS 1251,
QoS Null 1005, SSW 243, Ack 22, ATIM 21, SSW-FB 2, SSW-Ack 2, Action No Ack 2; чужих маяков 2456. Примеры (R39,
`a7.info0` → первые 16 Б): BA 08001840, 0x804 → `94 00 00 00` + свой + AP; Ack 08001c40, 0x380 → 10 Б без TA;
DMG CTS не нам 00013380 (R38 f0000000) → RA ff…, TA нули.

## 5. Драйвер

### 5.1. debugfs `capture`

```
start <сек> [mask=<список>|0xN] [snap=N] [dsnap=N] [bufs=N] [bufsize=N] [keep=0|1] [ch=N]
            [ts=tsf|host|raw] [raw=0|1] [fixta=0|1] [postdec=0|1]
stop
close
```

| опция | смысл, по умолчанию |
|---|---|
| `<сек>` | 1..86400, обязательна; по истечении — `stop` |
| `mask` | `rx` (= rxmgmt,rxctrl,rxbcn,rxerr,rxphy,rxsynth — **без rxqos**), `tx` (= txmgmt,txctrl,txbcn,txdirect — **без txqos**), отдельные биты, `rxqos`, `txqos`, `hostdata`, `hostmgmt`, `rxsynth`, `rxsynthbcn`; число: RX — биты 5..0, TX — биты 12..8, hostdata — 16, hostmgmt — 17, rxsynth — 18, rxsynthbcn — 19. По умолчанию `rx,tx` (0x41e3e). `rxqos`/`txqos` — только явно: AP под тяжёлым TX с ними висит (раздел 1), при старте — предупреждение в dmesg, в `capture` — строка `warning:`. `rxsynth` — синтетические кадры (4.2), нужен хотя бы один RX-бит; `rxsynthbcn` — ещё и чужие DMG Beacon, только вместе с `rxsynth` (иначе `-EINVAL`) |
| `snap` | байт кадра на тип, 4..252, кратно 4 (вверх); по умолчанию 252 |
| `dsnap` | то же для qos-данных (байт 0 регистров `max_data`); по умолчанию = `snap` |
| `bufs` | буферов в кольце 7, 2..32768; по умолчанию параметр модуля `capture_bufs` = 256 |
| `bufsize` | байт буфера, 64..32760, кратно 8 (пишется в 0x886080[27:16], 2.4); `capture_bufsize` = 2048 |
| `keep` | 1 — не освобождать кольцо после `stop`; `capture_keep` = 0 |
| `ch` | канал для Radiotap 1..6; иначе — канал AP/PCP-интерфейса или из последнего `connect` |
| `ts` | время записи pcap (`skb->tstamp`, его отдают AF_PACKET/tcpdump и `SO_TIMESTAMPNS`). `tsf` (по умолчанию): время хоста при старте + (TSF − TSF при старте) — одно линейное отображение на сеанс, порядок и интервалы — по TSF, файлы двух узлов сливаются по времени; скачок TSF виден как скачок времени. `host`: TSF через пару (TSF, время хоста) последнего опроса — идёт за часами хоста, может отступать на задержку чтения. `raw`: сам TSF как время от эпохи |
| `raw` | 1 — копии буферов PMC с дескрипторами в debugfs `capture_raw` (раздел 5.6); 0 (по умолчанию) — выкл. |
| `fixta` | 1 (по умолчанию) — восстанавливать последний байт TA в RX (раздел 4.1); 0 — кадр как записан, байт всё равно в `ta_raw` |
| `postdec` | 1 (по умолчанию, как vendor) — б16 `MAC_PRS_CTRL_0` на время записи; 0 — регистр не трогать (опыт: тот ли бит портит TA) |

`hostdata` (зеркало RX DMA: заголовок 802.11 из дескриптора, без тела) и `hostmgmt` (mgmt-кадры
`WMI_RX_MGMT_PACKET_EVENTID`) — по выбору, они дублируют PMC: вместе с `rxqos` / `rxmgmt` — `-EINVAL`. Маска только
из host-битов — PMC не включается, кольцо не нужно.

`close` — остановить, освободить кольцо и FIFO `capture_raw`, удалить `wilmon<N>`. `start` поднимает `wilmon<N>`
сам (раньше кадры при опущенном интерфейсе терялись: `ifdown` = 12 в первом прогоне). Модульные параметры:
`capture_cpu` — CPU опроса, `capture_raw_kb` — размер FIFO `capture_raw` (4096 КиБ, степень 2). Пока захват идёт,
`pmccfg alloc/free` отвергается (`-EBUSY`).

```
pmc: ctl=0x… stop_busy=… polls=…
bufs: du=… nodu=… by_last=… by_next=… du_early=… part=…
frames: rx=… tx=… bytes=… trunc=…
records: total=… phy_only=… tx_nohdr=… unknown=… orphan=… more=…
resync: N start=… garbage=… hole=… carry=… torn=…
ta: fixed=… unknown=… peers=…
tsf: bad=…
synth: ctrl=… mgmt=… data=… bcn=… bcn_skipped=… no_rule=…
drv: delivered=… ifdown=… no_mem=…
host: data=… mgmt=… no_mem=…
raw: entries=… unread=…/… dropped=… | raw: off
```

`head`/`tail`/`ctl` читаются из чипа только во время записи и при живой fw; иначе печатаются последние значения,
прочитанные или записанные за сеанс, с пометкой `(last)`, или `n/a` (раньше после останова — `0xffffffff`).
`pending` — буферов с DU, ждущих опроса; `du` / `nodu` — разобранные буферы с DU и без; `by_last` / `by_next` —
каким признаком буфер признан готовым (раздел 3); `du_early` — буферы, застигнутые с DU недописанными; `part` —
буферы, записанные не до конца; `max_fill` — наибольшее число буферов за один опрос; `full` — опросов, заставших
кольцо полным (PMC мог терять записи); `ifdown` — кадры при опущенном `wilmon`. `synth` — синтетические кадры по
классам слота (4.2), `bcn_skipped` — чужие маяки без `rxsynthbcn`, `no_rule` — слот без правила (не строится).
`phy_only` считает все RX-группы без байтов, построенные и нет.

### 5.3. Опрос и останов

- hrtimer 2 мс → work на ordered workqueue (CPU — `capture_cpu`); за опрос — до d−1 буферов; разобрано больше
  половины кольца — следующий опрос сразу.
- Чтения устройства за опрос: `SW_HEAD`, при данных — три чтения TSF (до первого буфера) и запись `SW_TAIL`. Сами
  записи — в памяти хоста (буфер копируется `memcpy` в промежуточный и разбирается). Опрос и чтение `capture` не
  трогают чип, пока fw не готова или идёт сброс.
- `stop` / лимит времени: останов PMC (2.2), дочитывание кольца вместе с недозаполненным буфером, закрытие групп,
  освобождение кольца (`WMI_PMC` op 1, если fw жива).
- `wil_reset` (FW error, `wil_down`), `suspend`: до сброса чипа опрос останавливается, PMC выключается регистрами
  (без WMI, без дочитывания), кольцо остаётся выделенным до следующего `start`/`close`. Если доступа к устройству
  уже нет — кольцо не освобождается (PMC мог бы писать в освобождённую память).

### 5.4. Radiotap

| бит | поле | значение |
|---|---|---|
| 0 | TSFT (u64, мкс) | кадры PMC: метка записи `a7`/`59` — начало PPDU (раздел 4), расширенная до 64 бит (раздел 4.1) |
| 1 | Flags (u8) | 0 — FCS в кадре нет; `hostdata`: BADFCS по дескриптору; синтетический: BADFCS по R38 |
| 3 | Channel | `56160 + 2160 × канал` МГц (класс 180, Table E-4), флаги 0; канал неизвестен — 0 |
| 5 | dBm Antenna Signal | только `hostmgmt` при `RSSI_REPORTING` |
| 22 | Timestamp | только host-зеркала: TSF, оценённый по времени хоста, position «unknown» |
| 30 + 31 | Vendor Namespace + Ext | OUI **02:53:52**, sub_ns 1, skip_length 60; следующее слово present — vendor, бит 0 |

Vendor-данные, версия 4 (60 Б, little endian; от версии 3 отличается `slot`/`sflags`/`reserved` в конце и `mcs`
у PMC RX; от версии 2 — `ta_raw`/`ta_cid` на месте `reserved` и битами 6, 7 `flags`):

```c
struct wil_cap_rt_vendor {
    u8     ver;        /* 4 */
    u8     src;        /* 5 — зеркало RX DMA, 6 — WMI mgmt, 7 — PMC */
    u8     dir;        /* 0 — принят, 1 — передан этим узлом */
    u8     flags;      /* б0 TRUNC, б1 TRAILER, б2 NOLEN, б3 TSF, б4 STATUS, б5 PHY,
                          б6 TA (ta_raw есть), б7 TA_FIXED (байт TA восстановлен) */
    u8     mcs;        /* DMG MCS, 0xff — нет; PMC RX — a7.info0[4:0], PMC TX — нет */
    u8     cid;        /* 0xff — нет; синтетический с TA_PEER — CID передатчика */
    __le16 mpdu_len;   /* без FCS, 0 — нет */
    __le16 caplen;
    u8     ta_raw;     /* RX: последний байт TA как записан */
    u8     ta_cid;     /* TA_FIXED: CID пира, иначе 0xff */
    __le32 tsf32;      /* метка записи как есть, мкс */
    __le32 info0;      /* RX: слово 1 записи a7; TX: слово 1 записи 59 */
    __le32 info1;      /* TX: слово 2 записи 59 */
    __le32 status;     /* RX: ae */
    __le32 trailer;    /* RX: 4 Б на месте FCS */
    u8     phy[24];    /* RX: af (w0 статус, w2..w5 R36..R39) */
    u8     slot;       /* RX с af: слот R39[13:8], иначе 0xff */
    u8     sflags;     /* 4.2: б0 SYNTH, б1 RA_OWN, б2 RA_UNKNOWN, б3 TA_PEER,
                          б4 TA_UNKNOWN, б5 BAD_FCS, б6 CDOWN0, б7 TSF_BAD */
    __le16 reserved;
};
```

MCS в поле HT не ставится (для DMG оно неверно). Lua-диссектор vendor-полей — впереди
(`tools/wireshark/sparraw_capture.lua`); пока поля видны в Wireshark как «Vendor Data».

### 5.5. Слияние двух узлов

Оба узла в TSF точки (станция принимает TSF точки; на стенде «свой TSF − Timestamp» постоянен, 12 мкс). Свою
передачу каждый узел пишет сам (TX-группы), так что слияние не нужно для «что я послал», только для «что принял
пир».

`tools/pcap_merge_tsf.py` драйвера: `pcap_merge_tsf.py -o both.pcapng ap.pcap:AP sta.pcap:STA` — порядок по
Radiotap TSFT (кадр без TSFT — по времени pcap через медиану «время pcap − TSFT» своего файла); кадр, записанный
обоими узлами (те же байты MPDU, TSFT в пределах `--window`, 2 мкс), пишется один раз с комментарием
`AP+STA dt=…`; выход — pcapng, интерфейс на узел (`if_name` = метка), у каждого пакета комментарий-источник
(`AP rx`, `STA tx`; направление из vendor-поля). Метки TX и RX одного кадра могут стоять в разных точках PPDU
(обе — начало PPDU, но задержки защёлки TX и RX разные): `--auto-offset` оценивает сдвиг B по парам одинаковых кадров в окне `--search`
(500 мкс) и печатает медиану; `--offset-b` задаёт его руками. Проверка: `--selftest [pcap]` (разрезает файл на
два узла с копиями ±1 мкс и сдвигом 37 мкс). Простой `mergecap` тоже работает при `ts=tsf` на обоих, но без
дедупликации.

### 5.6. debugfs `capture_raw` (опция `raw=1`)

Для разбора потока на хосте: каждый разобранный буфер PMC идёт ещё и в FIFO ядра (по умолчанию 4 МиБ,
`capture_raw_kb`) записью «заголовок + буфер как прочитан». Чтение файла забирает данные из FIFO (`cat` до
пустого); FIFO полон — запись отбрасывается, номер `seq` всё равно растёт (пропуск виден). Данные живут до
следующего `start` или `close`.

Заголовок (120 Б, little endian, `struct wil_cap_raw_hdr`): `magic` "WCR1", `hdr_len`, `type` (1 — буфер,
2 — старт, 3 — стоп), `seq`, `idx` дескриптора, `len` буфера, `flags` (б0 DU, б1 готов по последнему слову,
б2 готов по началу следующего, б3 взят при останове, б4 застигнут ранее с DU недописанным, б5 DU у следующего),
`hw_head` (`SW_HEAD` этого опроса), `hw_tail` (последний записанный `SW_TAIL`), `host_ns`, `tsf` (TSF этого
опроса; у старта — TSF при старте), `polls`, `ring_n`, `desc[32]` и `desc_next[32]` — дескрипторы i и i+1 как
есть до возврата (в т. ч. `status` и `length`, которые пишет аппаратура).

Разбор: `tools/pmc_decode_test.py --raw raw.bin [-v] [--peer 24:18:1d:24:3b:0b=0] [--own 24:18:1d:26:d4:7b]
[--synth 0|1|3]` — построчно буферы с флагами,
полями дескрипторов и записанной частью (`-v`, без него — только буферы с потерей синхронизации), пропуски `seq`
и скачки индекса, итоговые счётчики разборщика (те же, что у драйвера) и кадры по типам.

## 6. Использование на стенде

```sh
D=/sys/kernel/debug/ieee80211/phy0/wil6210
echo "start 60" > $D/capture                        # rx,tx без данных + rxsynth; 256 × 2048 Б; ts=tsf
echo "start 10 mask=rx,tx,rxqos,txqos" > $D/capture # с данными: только без тяжёлого TX (раздел 1)
echo "start 30 mask=tx,rxbcn,rxmgmt snap=64" > $D/capture
echo "start 20 raw=1" > $D/capture                  # + сырые буферы в capture_raw
tcpdump -i wilmon0 -s0 -U -w /tmp/cap_$(hostname).pcap &   # или: wilcap wilmon0 60 > /tmp/cap.pcap
cat $D/capture                                      # счётчики; через 60 с state: stopped
cat $D/capture_raw > /tmp/raw.bin                   # можно и по ходу: чтение освобождает FIFO
echo stop > $D/capture                              # досрочно
echo close > $D/capture                             # убрать wilmon0, кольцо и FIFO
```

На узлах без tcpdump — `tools/wilcap/wilcap.c` драйвера: AF_PACKET → pcap (radiotap, наносекунды) в stdout,
время записи — метка skb (`SO_TIMESTAMPNS`), т. е. время по `ts=`, а не момент чтения. Сборка:
`arm-openwrt-linux-muslgnueabi-gcc -O2 -Wall -o wilcap tools/wilcap/wilcap.c`; запуск с хоста:
`ssh root@10.60.0.12 'wilcap wilmon0 15' > cap.pcap` (параллельно с `start 15`).
Сырые буферы с хоста: `ssh root@10.60.0.12 'cat /sys/kernel/debug/ieee80211/phy*/wil6210/capture_raw' > raw.bin`,
затем `tools/pmc_decode_test.py --raw raw.bin -v`.

С хоста: `rewrite/tools/capture.sh 30 11 12` (оба узла, pcap сюда, слияние `mergecap`).

Плата — lowpwr3 на обоих узлах (проверить md5 до серии).

## 8. Что сделано и что убрано

- Драйвер: `capture.c` переписан под PMC; `pmc.c` — кольцо без `DMA_IT`, переиспользование, владение кольцом
  захватом (`pmccfg` в это время отвергается); удалены `WMI_SPARRAW_CAPTURE_*`; бит 24 — `RAW_MODE`;
  канал STA запоминается из события `connect`.

  `sflags`, `mcs` у PMC RX); маска по умолчанию без записей данных (`rxqos`/`txqos` только явно, с
  предупреждением). Автоматического снятия `txqos` по темпу TX-записей нет: зависание наступает за секунды, порог

  `wmi_cmd.c`/`uc/sched.c` ветки `feat/capture` относятся к отменённой схеме и в open не идут.
