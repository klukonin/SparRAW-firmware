# Архитектура: ядро стандарта отдельно от железа

Цель — одно прочтение 802.11-2020 (DMG MAC), не зависящее от железа, которое:

- исполняется как MAC станции и точки/PCP (не только проверяет записи);
- работает в идеальной среде, на эмуляторе Sparrow вместо прошивки и (позже) поверх Talyn;
- сравнивается по поведению с прошивкой C11 — для поиска граничных случаев и проверки гипотез без правки прошивки;
- служит фундаментом для кода Talyn.

Опора одна — текст стандарта `docs/80211-2020.txt`. Вендорское поведение — не эталон (только факты о регистрах и
командах MAC).

## Слои

```
            ┌───────────────────────────────────────────────────────────┐
  стандарт  │ docs/80211-2020.txt                                       │
            └───────────────────────────────────────────────────────────┘
            ┌──────────────────────┐   ┌──────────────────────────────────┐
  ядро      │ ref/core  (Python)   │   │ fw C11: ядро стандарта (rewrite/ │
  стандарта │ исполняемые автоматы │   │ fw — постепенно)                 │
            │ STA, AP/PCP          │   │ независимая реализация           │
            └──────────┬───────────┘   └───────────────┬──────────────────┘
          MAC-SAP ↑ MLME-SAP ↑                          │
          PHY-SAP ↓ + точки разгрузки ↓                 │
            ┌──────────┴────────────────────────────────┴──────────────────┐
  адаптеры  │ идеальная среда │ Sparrow (эмулятор: machw/air) │ Talyn (позже)│
            └──────────────────────────────────────────────────────────────┘
            ┌───────────────────────────────────────────────────────────┐
  судьи     │ ref/* (проверки, air_judge) — по журналу событий/записи   │
            └───────────────────────────────────────────────────────────┘
```

### 1. Ядро референса — `rewrite/tests/ref/core/`

Исполняемые автоматы DMG MAC по стандарту: BI (BTI/A-BFT/ATI/DTI), SLS/BRP, ассоциация, CBAP/EDCA, BlockAck,
расписание DTI (SP, PP/GP), сопровождение луча, Link Measurement, кластеризация и т.д. Про регистры, очереди MAC и
такты ничего не знает. Вырастает из уже существующих моделей (`dmg_sta.py`, `cbap.py`, `sls.py`, `abft.py`,
`blockack.py`, `schedule.py`, `sp.py`, `dynalloc.py`, …) — без копирования логики прошивки.

Интерфейсы ядра — те, что задаёт стандарт:

| Сторона | Интерфейс | Пункт 802.11-2020 |
|---|---|---|
| вверх, данные | MA-UNITDATA.request / .indication / -STATUS.indication | 5.2 |
| вверх, управление | MLME-SAP (Scan, Associate, Start, Block Ack, Link Measure, BF-TRAINING, …) | 6.3, 6.5 |
| вниз | PHY-SAP: PHY-TXSTART/TXEND/DATA, PHY-CCA, PHY-CCARESET, PHY-RXSTART/RXEND, PHY-CONFIG; TXVECTOR/RXVECTOR | 8.3.5 |

Время ядра — модельное (мкс с дробью), события — по PHY-SAP. Все сроки — из стандарта (SIFS, SBIFS, MBIFS, aSlotTime,
TXTIME — `ref/timing.py`).

### 2. Точки разгрузки

Железо выполняет часть стандарта само. Чтобы ядро осталось независимым от железа, у адаптера есть набор
**точек разгрузки** — функций, которые берёт на себя железо; ядро их в этом случае не делает, а получает о них
события.

| Точка разгрузки | Идеальная среда | Sparrow (факты стенда) |
|---|---|---|
| немедленный ответ через SIFS (Ack, BlockAck, DMG CTS) | ядро | MAC (ответ через ~4,5 мкс, MAC-STAND) |
| Duration RTS и кадров очереди | ядро | MAC (остаток лимита TXOP, H-DURQ) |
| backoff / доступ EDCA | ядро | MAC (CWmin, AIFS, слот) |
| NAV | ядро | MAC |
| BlockAck: scoreboard получателя | ядро | MAC (BAP) |
| вставка Timestamp в маяк | ядро | MAC (движок маяка) |
| развёртка SSW / сетка A-BFT | ядро | uc + MAC (GP-таймеры) |

Расхождение «ядро с разгрузкой Sparrow» ↔ «ядро в идеальной среде» = место, где железо ведёт себя не по стандарту
(или допущение модели неверно). Список точек — часть интерфейса адаптера; добавляется по мере появления фактов.

### 3. Адаптеры

- **Идеальная среда** (`ref/core/medium_ideal.py`): кадры, CCA и задержки строго по стандарту, без разгрузки.
- **Sparrow** (`ref/core/adapter_sparrow.py`): ядро работает поверх модели MAC эмулятора (`tests/unit/machw.py`,
  эфир `air.py`) — на том же «железе», что и прошивка. Точки разгрузки — по фактам MAC-STAND и допущениям H-*.
- **Talyn** — позже, тот же интерфейс.

### 4. Прошивка C11

- Ядро референса и ядро прошивки — **две независимые реализации** одного стандарта. Общие — структура и
  интерфейсы, не логика: общая ошибка прочтения иначе не ловится сравнением. Спорные места стандарта — трактовки
  `ref/PLAN.md`.
- Деление fw на ядро стандарта и слой железа — точечно: MLME, BlockAck, расписание/TDMA, политика BF — там, где это
  даёт пользу для Talyn. uc и пути со сроками (ХРУПКО) не трогаются. Каждый шаг — codecmp ХРУПКО без изменений,
  контроль размера кода и тактов, стенд.

### 5. Судьи

Существующие проверки `ref/*` и `air_judge` остаются судьями. Они применяются к журналу событий ядра, к журналу
эмулятора и к записи PMC стенда — одними и теми же правилами.

## Тесты

| Уровень | Что |
|---|---|
| юнит | каждый модуль ядра, адаптера, судьи; прошивка в эмуляторе (как сейчас) |
| интеграция 1 | ядро ↔ ядро в идеальной среде (точка + станция), судья 0 нарушений |
| интеграция 2 | прошивка в эмуляторе против ядра в идеальной среде — сравнение по журналам через судью |
| интеграция 3 | ядро на адаптере Sparrow; смешанные пары: точка-ядро + станция-прошивка и наоборот |
| стенд | последний арбитр; допущения H-* проверяются стендом |

Расхождение на эмуляторе может быть ошибкой модели MAC — решает стенд.

## Этапы

| Этап | Содержание | Готово, когда |
|---|---|---|
| 1 | Интерфейсы (PHY-SAP 8.3.5, MAC-SAP 5.2, MLME-SAP 6.3) и ядро-минимум: BTI, A-BFT, SLS в DTI, ассоциация, данные CBAP с BlockAck; идеальная среда | точка и станция на ядре соединяются и гоняют данные; судья — 0 нарушений; тесты |
| 2 | Сравнение по эфиру: прошивка в эмуляторе против ядра в идеальной среде (тот же сценарий, журналы через судью) | автоматический отчёт расхождений по сценариям |
| 3 | Адаптер Sparrow с точками разгрузки; смешанные пары в эмуляторе | ядро-точка + прошивка-станция и наоборот работают; расхождения классифицированы |
| 4 | Расширение ядра: BRP, сопровождение луча, строгий TDMA (SP, PP/GP), кластеризация, Link Measurement, … | каждый пункт — в ядре, в сравнении и смешанных парах |
| 5 | Прошивка: ядро стандарта отдельно от слоя железа (точечно, без ХРУПКО) | codecmp ХРУПКО без изменений, размер/такты, тесты и стенд — как раньше |
| 6 | Talyn: скелет адаптера на том же ядре | базовый сценарий в эмуляции Talyn |
