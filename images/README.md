# Образы прошивки и board-файлы

Контрольные суммы — `SHA256SUMS` (`sha256sum -c SHA256SUMS` из этого каталога).

| каталог | что |
|---|---|
| `vendor/` | вендорские оригиналы без изменений |
| `openwrt/` | то, что ставится в OpenWrt как есть: `fw/` → `/lib/firmware/wil6210.fw`, `brd/` → `/lib/firmware/wil6210.brd` |
| `sparraw/` | наши сборки |

## vendor/

| файл | откуда |
|---|---|
| `fw/wil6210_4.1.0.1000.fw` | RouterOS 6.42.1, `wireless-6.42.1-arm.npk` → `lib/firmware/wil6210.fw` |
| `fw/wil6210_6.2.0.1000.fw` | RouterOS `wireless-*.npk` (расшифрованный); та же сборка есть у UBNT airFiber 6.2.0.225 |
| `fw/wil6210_5.2.0.18.fw` | linux-firmware (`wil6210.fw`); в OpenWrt ставится пакетом `wil6210-firmware` |
| `brd/wil6210-<модель>.brd`, `.msg` | RouterOS 6.46.x, `lib/firmware/` — как в пакете, зашифрованные |
| `brd/decrypted/` | те же board-файлы после снятия шифра. Формат RouterOS (3516 Б, заголовок `02000000`), драйвером не принимается |

Образы RouterOS несут вендорские записи 100/101/102, которые драйвер OpenWrt не
понимает. Распаковка npk: `SparRAW-tools/re/npk_unpack.py`, при необходимости
`npk_decrypt.py --auto`.

## openwrt/

| файл | что |
|---|---|
| `fw/wil6210_4.1.0.1000.fw`, `fw/wil6210_6.2.0.1000.fw` | вендорские образы без записей RouterOS (`fw_strip_for_openwrt.py`); код не изменён. Это эталоны побайтовой сверки `make fw` в `4.1/` и `6.2/` |
| `fw/wil6210_6.2.0.1000-fix.fw` | 6.2.0.1000 с исправлениями ошибок вендора и ничем больше (версия `6.2.0.1000-fix-EWM`), для ванильного драйвера; `cd 6.4 && make fw VARIANT=fix`, состав — `6.4/variants/fix.txt` |
| `brd/wil6210-<модель>.brd` | board-файлы в формате драйвера (3576 Б, заголовок `06000000 34000000 "0126"`) |

### 6.2.0.1000-fix

От вендорского `wil6210_6.2.0.1000.fw` отличается только в перечисленных местах;
остальной код, данные fw, `direct_write` и таблицы AGC — побайтово вендорские.
Новых режимов, функций и возвращённой печати 4.1 нет.

| ошибка 6.2 | исправление |
|---|---|
| станция глуха в DTI: после BRP приём через «направленный omni» (пинг ~30 %) | всегда quasi-omni, как у точки (`uc/brp_update_omni_sector_idx`) |
| Probe Response сообщает интервал маяка 100 TU при любом `beacon_int` | интервал из настройки хоста (`fw/l2_mgr__pcp_start_flow`) |
| четвёртая аллокация ESE — фатальная ошибка 0x11bb | лишняя аллокация пропускается (`fw/ese__slot_table_add`) |
| конец слота A-BFT на 20 мкс дальше aSSSlotTime (10.42.5.2) | патч 0003 |
| слот A-BFT из [0, поле): при двух слотах всегда первый, при одном — пусто | [0, поле + 1), как в 4.1 (патч 0008) |
| Reassociation Request/Response от соседа — fatal assert | кадр отбрасывается (патч 0009) |
| станция отбрасывает маяки точки с CBAP Only = 0 (стандартная точка с ESE) | патч 0011 |
| split MAC: кадр hostapd без соединения — нет `SW_TX_COMPLETE`, драйвер ждёт 2 с | завершение со статусом 1 (патч 0017) |
| после снятия ESE нулевые окна SP останавливают передачу | патч 0020 |
| интервал маяка станции берётся только из команды хоста 0x803; мейнлайн шлёт в ней `WMI_ECHO` 0x12345678 → BI 0x5678 TU, разрыв каждые 2–4 с | из маяка выбранной точки, 802.11-2020 11.1.3.3.1 (`fw/new/sta_bi`, `fw/wmi_connect`, патч 0022) |

Работает с ванильным драйвером wil6210 (backports, без патчей SparRAW).

Board-файл выбирается по модели, от него зависит качество линка:

| модель | board-файл |
|---|---|
| wAP 60G | `wap60g-60deg` |
| wAP 60Gx3 | `wap60g-omni` |
| LHG 60G | `lhg-span2.8` |
| Cube 60G | `cube` |
| nRAY | `nray` |

Для `wap60g-sa-dir` и `wap60g-sa-omni` (формат 6668 Б) версии для драйвера нет.

## sparraw/

| файл | что |
|---|---|
| `wil6210-6.4-apsta.fw` | 6.4.0.1, вариант apsta (AP, STA, PBSS); `cd 6.4 && make release` |
| `wil6210-6.4-mesh.fw` | 6.4.0.1, вариант mesh (DMG IBSS) |
| `experimental/` | промежуточные образы и board-файлы опытов; в выпуск не входят |

Оба образа 6.4 ставятся в OpenWrt вместо `wil6210.fw` вместе с драйвером
из `SparRAW-driver`.
