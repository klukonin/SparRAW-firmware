# src/ext — дополнительный код, добавляемый к прошивке

Сюда кладутся модули на C, которые собираются тулчейном ARC и линкуются
в **свободный хвост** `fw_code` (секция `.text.ext`, см. `ld/memory.ld`),
не затрагивая ни одного байта вендорского кода.

Свободно в 4.1.0.1000: fw_code 50344 Б (с 0x8f3b58), uc_code 32572 Б.

Вызов вендорских функций — по адресам из `ref/SYMS.txt` через
`ld/symbols.ld` (генерация — `make symbols`).
Встраивание в существующий поток — трамплинами.

## Хуки

Перехват вендорской функции — три шага:

    make hook AT=0x8c2190 HANDLER=ext_on_tx_bcon   # анализ + трамплин
    make ext                                       # собрать дополнительный код
    make hook-overlay AT=0x8c2190                  # патч-переход

`tools/mkhook.py` сам решает, сколько байт можно вытеснить, и **отказывается**,
когда перенос небезопасен.

Что он учитывает в ARC:
* инструкции разной длины (2/4/6/8 Б) — вытесняются только целиком;
* **слот задержки**: у перехода с `.d` следующая инструкция является его частью,
  разрывать пару нельзя;
* PC-относительные инструкции при переносе меняют смысл. Переходы с известной
  целью переписываются текстом (линкер считает новое смещение), а аппаратный
  цикл `lp` переносить нельзя вообще — такой хук отклоняется;
* ассемблер не всегда даёт ту же кодировку, что в образе, поэтому непереходные
  инструкции переносятся **дословно байтами**.

Трамплин сохраняет r0–r7, r12 и blink перед вызовом обработчика: при хуке на
входе функции в этих регистрах лежат её аргументы.

**Патч сам по себе неполон.** Он ведёт в область, которой в вендорском образе
нет. Прошивать можно только образ, куда добавлена запись с `build/ext.bin`
 (`make image`).
